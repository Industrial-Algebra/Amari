# Amari v0.22.0 CGT / Surreal Completeness Backlog

## Purpose

This backlog captures the **additional completeness work** to pursue for `amari-cgt` and `amari-surreal` while the project is still waiting on the earlier `0.20.0` and `0.21.0` release cycles.

The goal is to use that runway to make the `0.22.0` CGT/surreal release more complete and better integrated, **without letting scope explode**.

---

## Scope Guardrails

The following remain out of scope for this backlog:

- loopy games
- misère play
- scoring play
- thermographs / temperatures
- hyperreal or nonstandard-analysis machinery
- full symbolic surreal universes
- surcomplex implementation inside `amari-surreal`

`amari-surcomplex` remains a **separate later crate** depending on a mature `amari-surreal`.

---

## Pass A — `amari-surreal` Completeness

### Goal

Strengthen `amari-surreal` as a mature short-surreal numeric layer and a future dependency point for `amari-surcomplex`.

### Backlog

- [x] separate division-by-zero from non-dyadic division failure
- [x] add checked reciprocal helpers for `Dyadic` and `ShortSurreal`
- [x] improve dyadic division so supported quotients succeed even when the divisor reciprocal is not itself dyadic
- [x] add total ordering for `ShortSurreal`
- [x] add sign/absolute-value convenience methods for `Dyadic` and `ShortSurreal`
- [x] add `ShortSurreal::to_game_in(&mut GameArena)` reconstruction
- [x] add round-trip tests for `game -> ShortSurreal -> game`
- [x] add round-trip tests for `dyadic -> ShortSurreal -> game -> ShortSurreal`
- [x] confirm reconstructed games are numeric and birthday-consistent for standard examples

### Acceptance criteria

- supported dyadic quotients succeed exactly
- unsupported non-dyadic quotients fail with a distinct error from division by zero
- `ShortSurreal` behaves like an ordered numeric type in the short-surreal layer
- short surreal values can be reconstructed back into canonical numeric short games
- round-trip tests pass for a curated corpus of standard dyadics

## Execution Order

Recommended order of work:

1. **Pass A — `amari-surreal` completeness**
2. **Pass B — `amari-cgt` public-shape and ergonomics**
3. **Pass C — analysis and reporting polish**

This order keeps the scalar layer solid first, then improves the foundational game engine interface, then refines the surrounding analysis tools.
