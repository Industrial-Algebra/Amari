# Arbitrary-Signature WASM Multivector Support

Date: 2026-05-23
Status: Design
Target: Amari v0.23.0
Issue: [#161](https://github.com/justinelliottcobb/Amari/issues/161)

## Motivation

The Amari WASM bindings currently support only two Clifford algebra signatures via
concrete per-signature types (`WasmMultivector` for Cl(3,0,0) and
`WasmSpacetimeMultivector` for Cl(2,1,0)). Adding each new signature requires
duplicating ~150 lines of Rust and ~200 lines of TypeScript. This does not scale
to the range of signatures users need — Minkowski spacetime Cl(3,1,0),
conformal GA Cl(4,1,0), quaternion algebra Cl(0,3,0), and others.

The goal is to replace the per-signature concrete types with a single
`WasmGenericMultivector` that accepts a runtime signature `(p, q, r)` and
dispatches correctly. Eight common signatures get fast-path aliases (compile-time
monomorphized dispatch); all other signatures up to DIM ≤ 6 use the same macro-
generated match table; and signatures beyond DIM > 6 fall through to a generic
Cayley-table path with no practical limit.

### Match-table dispatch (DIM ≤ 6)

All 84 signatures `(p, q, r)` where `p + q + r ≤ 6` are enumerated in a
`match` generated by a build script (`amari-wasm/build.rs`). For each arm, the
generic `WasmGenericMultivector` constructs temporary `Multivector<P, Q, R>`
values, calls the correct monomorphized method, and extracts the result
coefficients back into a `WasmGenericMultivector`.

The match table covers:

- DIM 0: 1 signature (0,0,0) — scalar algebra
- DIM 1: 3 signatures — (1,0,0), (0,1,0), (0,0,1)
- DIM 2: 6 signatures
- DIM 3: 10 signatures
- DIM 4: 15 signatures
- DIM 5: 21 signatures
- DIM 6: 28 signatures

Total: 84 match arms.

Performance: one match dispatch (effectively a jump table) plus the cost of
`from_coefficients` → `Multivector` → `geometric_product` → extract coefficients.
This is the same cost as the current "generic path" but with compile-time
optimization for each specific signature.

### Generic Cayley-table fallback (DIM > 6)

For signatures not in the match table, the fallback path computes a Cayley table
on first use:

```
blade_product(p, q, r, dim, i, j) -> (k, sign)
```

The Cayley table maps basis-blade pairs `(i, j)` to `(result_blade, sign)`.
It is cached per `(p, q, r)` triple (thread-local, lazily initialized) so
subsequent operations on the same algebra are table lookups.

Algorithm:
1. `k = i ^ j` (XOR for the result blade index)
2. Sign from reordering: parity of swaps needed to merge sorted bases
3. Sign from metric: for each k where bit is set in both i and j, multiply by
   metric(k) where metric(k) = +1 for k < p, -1 for p ≤ k < p+q, 0 for k ≥ p+q

The fallback is O(4^dim) on first use (building the table), then O(1) per
basis-blade pair for subsequent products.

### amari-core changes (additive only, no breakage)

Two new public functions in `amari-core`:

```rust
/// Compute the result blade index and sign for the geometric product of
/// basis blades i and j in Cl(p, q, r) of dimension dim = p+q+r.
pub fn blade_product(p: usize, q: usize, r: usize, dim: usize,
                     i: usize, j: usize) -> (usize, f64);

/// Compute the full geometric product of two multivectors given as
/// coefficient slices, in Cl(p, q, r).
pub fn generic_geometric_product(p: usize, q: usize, r: usize,
                                  a: &[f64], b: &[f64]) -> Vec<f64>;
```

These are pure, no-allocation (except the return Vec), callable from any crate.
They serve both the WASM fallback path and any future pure-Rust consumers that
need runtime signature selection.

### TypeScript API

A single `Multivector` class replaces all per-signature classes:

```typescript
// Arbitrary signature
const mv = new Multivector(2, 1, 0);
const e1 = Multivector.basis(2, 1, 0).e1();

// Fast-path aliases (pre-set p,q,r + named basis accessors)
const GA   = Multivector.euclidean3D();   // Cl(3,0,0)
const ST   = Multivector.spacetime2p1();  // Cl(2,1,0)
const MINK = Multivector.minkowski();     // Cl(3,1,0)
const PL   = Multivector.planar();        // Cl(2,0,0)
const QUAT = Multivector.quaternion();    // Cl(0,3,0)
const CGA  = Multivector.conformal();     // Cl(4,1,0)
const P5D  = Multivector.euclidean5D();   // Cl(5,0,0)
const S2D  = Multivector.split2D();       // Cl(1,1,0)

// Basis access (all aliases)
GA.e1().geometricProduct(GA.e2());  // returns e12
MINK.e0().geometricProduct(MINK.e0()); // returns 1 (timelike, squares to +1)
```

**Backward compatibility**: The existing `GA` export and `Multivector` class
continue working. The default constructor `new Multivector()` without arguments
defaults to Cl(3,0,0). The `ST` export is added. Existing code that does
`import { GA } from 'amari-wasm'; GA.e1();` is unchanged.

### Batch operations

`BatchOperations` and `PerformanceOperations` gain generic counterparts:

```typescript
// Generic batch geometric product
BatchOperations.batchGeometricProduct(a, b, p, q, r);

// Fast-path batch (uses match table)
BatchOperations.batchGeometricProductEuclidean3D(a, b);  // Cl(3,0,0)
BatchOperations.batchGeometricProductMinkowski(a, b);    // Cl(3,1,0)
// ... same pattern for all 8 aliases
```

## Fast-path aliases

| Signature   | Rust struct name           | TS factory            | Use case |
|-------------|---------------------------|-----------------------|----------|
| Cl(3,0,0)   | `WasmMultivector300`      | `euclidean3D()` / GA  | 3D rotations, graphics |
| Cl(2,1,0)   | `WasmMultivector210`      | `spacetime2p1()` / ST | 2+1 physics |
| Cl(3,1,0)   | `WasmMultivector310`      | `minkowski()` / MINK  | 3+1 relativity |
| Cl(2,0,0)   | `WasmMultivector200`      | `planar()` / PL       | 2D geometry, complex numbers |
| Cl(0,3,0)   | `WasmMultivector030`      | `quaternion()` / QUAT | Pure quaternion algebra |
| Cl(4,1,0)   | `WasmMultivector410`      | `conformal()` / CGA   | Conformal GA (translations as rotors) |
| Cl(5,0,0)   | `WasmMultivector500`      | `euclidean5D()` / P5D | 5D Euclidean, projective GA |
| Cl(1,1,0)   | `WasmMultivector110`      | `split2D()` / S2D     | Split-complex / 1+1 spacetime |

Each fast-path alias is a concrete `#[wasm_bindgen]` struct generated by the
existing `wasm_multivector!` macro. They exist for:
1. Direct JS interop (no runtime signature overhead)
2. Named basis-vector accessors in TypeScript
3. Batch operations pre-specialized to a known signature

## Breaking Changes

**amari-core**: None. Additive only.

**amari-wasm (Rust)**: The existing `WasmMultivector`, `WasmSpacetimeMultivector`,
`WasmRotor`, and `WasmSpacetimeRotor` types are replaced. New exports:
- `WasmGenericMultivector` (the general-purpose type)
- `WasmGenericRotor` (general-purpose rotor)
- 8 fast-path concrete structs (one per alias, named by signature)

**TypeScript**: The existing `Multivector` class is replaced with a version that
accepts `(p, q, r)` in its constructor. The default `new Multivector()` without
arguments still produces Cl(3,0,0). All existing static methods (`GA.e1()`, etc.)
remain. The `GA`, `ST` convenience exports are preserved.

## Non-goals

- No GPU integration for generic signatures
- No changes to other amari-* crates
- No changes to `amari-relativistic` (which already handles Cl(1,3,0) internally)
- No examples-suite updates beyond import adjustments
- No surcomplex or rewrite integration

## Testing strategy

1. **Fast-path identity tests** — for each of the 8 aliases, verify basis-vector
   squares match the expected metric signature
2. **Match-table correctness** — for a random sample of 20 signatures with
   DIM ≤ 6, verify that `WasmGenericMultivector` geometric products match the
   known-good `Multivector<P, Q, R>` results
3. **Fallback correctness** — for DIM 7 and 8, verify basis-vector products
   match the metric
4. **Cayley-table caching** — verify that the second product on a signature is
   faster than the first (the table is cached)
5. **Edge cases** — zero multivectors, mismatched-signature operations (should
   error), DIM=0 (scalar algebra), negative squares for all-negative signatures
