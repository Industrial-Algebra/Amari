## 3. Phases (foundations-up)

Per-crate treatment = the amari-core template, scaled: file-by-file
census (math first, in contribution chronology) → bounded remediation
contract with operator decision points → TDD remediation → 12-round
review loop → operator merge. Standing rules all inherit: correctness
paramount over compatibility, evidence slimming, TOTAL-override
runners, fail-closed gates, richer-substrate remedy direction.

- **Phase A — leaf math (core-only deps):** **amari-holographic first**
  (external consumer tracedecay — the only third-party semver promise in
  the set), then amari-dual, **amari-relativistic** (no integration
  surface — highest coverage-shape risk), amari-tropical (leaf:
  core-only deps; directly consumed by Quantizon).
- **Phase B — cgt subtree + unlocked leaves:** amari-cgt, amari-surreal,
  amari-flynn (+macros), **amari-automata** (deps core+dual+tropical all
  complete after Phase A).
- **Phase C — aggregating math:** amari-enumerative (core+cgt — cgt
  done in Phase B).
- **Phase D — the machine:** amari-gpu. Its 15 DIRECT dependencies,
  every one classified: **audited-in-this-programme (7)** — core
  (Phase 0, done), dual, relativistic, holographic (Phase A),
  tropical, automata, enumerative (Phase C); **dispositioned-not-
  audited (8)** — info-geom, network, measure, calculus, fusion,
  functional, topology, probabilistic. (cgt is transitive via
  enumerative, not direct.) gpu's audit therefore does NOT inherit
  audited-dependency guarantees for those eight: gpu's own contracts
  must pin its expectations of their behavior (its 31 test files are
  the starting surface), and any finding that lands in a dispositioned
  dep triggers a scope decision rather than a silent assumption.
- **Slot E — amari-core C4-full:** annotation repair → obligation
  inventory → proofs → replay (the 18-error taxonomy from #351 is its
  opening evidence). Position in the sequence is operator's call; it
  has no cross-crate dependency.

Estimates (from the core programme's actuals): each leaf crate
(2–8K LOC) ≈ a W-series package (contract+impl+loop, days not weeks);
enumerative/gpu are M-REP-scale (weeks). The no-integration-surface crates (relativistic, automata) require
test-battery construction BEFORE remediation can be verified — that is
in-scope work, not a precondition.

## 4. Dispositions for everything else

Non-consumed crates (measure, probabilistic, functional, fusion,
topology, calculus, network, optimization, dynamics, surcomplex,
**info-geom (R1: declared-unused by Starstrider, no other consumer)**,
discovery stack, rewrite stack) receive a one-line documented
disposition each — AUDITED-ELSEWHERE (rewrite cohorts 1–7),
NOT-ACTIVELY-CONSUMED (frozen as-is), or REMOVAL-CANDIDATE (operator
decision) — recorded in this document when approved. Nothing silent.
